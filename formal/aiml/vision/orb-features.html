ORB Features

Fast corners, a binary fingerprint and an orientation: features quick enough for a phone.

What is ORB?

Oriented FAST and Rotated BRIEF

A combination

  • FAST: corner detection
  • BRIEF: binary descriptor
  • Additions: orientation, scale pyramid

Advantages

  • Very fast (real-time capable)
  • Binary descriptor (fast matching)
  • Free and open source
  • Good performance

Use cases: mobile devices, embedded systems, real-time applications.

The ORB algorithm

FAST keypoint detection: find corners quickly

Harris corner measure: rank them and keep the top N

Scale pyramid: detect at multiple scales

Orientation assignment: the intensity centroid method

Rotated BRIEF: a binary descriptor aligned with that orientation

FAST, the detector inside ORB

FAST (Features from Accelerated Segment Test) checks the 16 pixels on a circle around a candidate.

If N consecutive pixels are all brighter than \(p + t\) or all darker than \(p - t\), it is a corner. ORB uses N = 9.

brighterdarkersimilarlongest run

Only simple comparisons, so it is very fast. ORB's improvement: rank the corners with the Harris measure and keep the best.

Orientation assignment

Problem: BRIEF is not rotation invariant. Solution: compute an orientation, then rotate the BRIEF pattern to match.

Intensity centroid of the patch around the keypoint:

  1. Moments: \(m_{pq} = \sum x^p\, y^q\, I(x, y)\)
  2. Centroid: \(C = (m_{10}/m_{00},\ m_{01}/m_{00})\)
  3. Orientation: \(\theta = \operatorname{atan2}(m_{01}, m_{10})\)

Result: turn the image and θ turns with it, so a descriptor measured relative to θ stays the same: rotation invariance.

The BRIEF descriptor

BRIEF: Binary Robust Independent Elementary Features.

  1. Select pairs of pixels in the patch
  2. Compare intensities: \(I(p_1) < I(p_2)\) gives 1, otherwise 0
  3. Concatenate the bits into a binary string

256 pixel pairs → 256 comparisons → 256 bits (32 bytes). Very fast to compute and to match: XOR and a bit count.

ORB matching

Distance metric: Hamming distance, the count of differing bits. Fast: XOR plus a bit count.


        # create ORB matcher (Hamming distance)
        bf = cv2.BFMatcher(cv2.NORM_HAMMING, crossCheck=True)  # ans:
        # detect in two images
        orb = cv2.ORB_create()
        kp1, des1 = orb.detectAndCompute(gray1, None)
        kp2, des2 = orb.detectAndCompute(gray2, None)
        # match
        matches = bf.match(des1, des2)  # ans:
        matches = sorted(matches, key=lambda x: x.distance)  # ans:

ORB vs SIFT

ORB advantages

  • Speed: 10 to 100× faster
  • Binary: fast matching (Hamming)
  • Free: no patent issues
  • Memory: 32 bytes vs 512 bytes (SIFT)

SIFT advantages

  • Accuracy: more distinctive
  • Robustness: better invariance
  • Difficult scenes: performs better
ORB
32 bytes: 256 bits
SIFT
512 bytes: 128 floats × 4 bytes

Choice: ORB for speed, SIFT for accuracy.

Scale pyramid

Why? The same feature can appear at different sizes, so ORB detects features at several scales. Level k is the image shrunk by \(\text{scaleFactor}^k\).

The WTA_K parameter

WTA_K is the number of points compared in each BRIEF test.

WTA_K=2

Compare 2 points: one bit per test (the default, 256 bits). Match with NORM_HAMMING.

WTA_K=3

Compare 3 points; the test outputs which is brightest (2 bits). More robust.

WTA_K=4

Compare 4 points (2 bits). Even more robust. For 3 or 4, match with NORM_HAMMING2.

Trade-off: robustness vs speed.

A binary descriptor, simple comparisons and fast matching.

How does ORB handle rotation?

It assigns an orientation using the intensity centroid.

What is scaleFactor?

The scale ratio between pyramid levels.

The advantage of binary descriptors?

Fast to compute and to match (XOR + bit count).

The ORB vs SIFT trade-off?

ORB is faster but less accurate; SIFT is slower but more robust.
